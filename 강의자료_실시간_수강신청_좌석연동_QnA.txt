--------------------------------------------------------------------------------
Part 1. 왜 정적 코드 상태로는 배포 후 실시간 좌석 공유가 안 될까?
--------------------------------------------------------------------------------

[질문 1]
이 웹앱은 강의를 위해서 예약된 인원을 넣어 놓고 마감 여부를 체크하고 있어.
그런데 내가 이 웹앱을 실제로 사용해서 수강신청을 받게 되면, 이 코드를 배포했을 때 A라는 수강신청자가 '엑셀 실무'를 2개 강의 신청을 했으면 그것이 반영돼서 B라는 수강신청자가 배포된 웹앱에 접근해서 '엑셀 실무' 강의를 신청하려고 하면 9명이 신청되어 있는 상태가 되어서 1명만 더 신청할 수 있도록 되어 있어야 하잖아.
이 프로그램은 배포되었을 때 그것이 가능하도록 되어 있어?

[답변 1]
결론부터 정확히 말씀드리면, 지금 상태 그대로 배포하면 불가능합니다.

현재 프로그램이 어떻게 동작하고 있는지, 그리고 실제로 가능하게 만들려면 무엇을 보완해야 하는지 정리해 드립니다.

1. 현재 코드의 상태 (왜 지금 배포하면 안 될까?)

  ① 초기 예약 인원(booked)이 파일에 고정(하드코딩)되어 있습니다.
     - data/courses.js에 '엑셀 실무'가 seat: 10, booked: 7로 적혀 있습니다.
     - A 수강생이 2명을 신청하면 구글 시트에는 기록이 남고 A의 화면에서는 9명으로 보이지만, 웹앱이 구글 시트에서 다시 신청 인원을 읽어오지는 않습니다.
     - 따라서 B 수강생이 접속(또는 A가 새로고침)하면 여전히 파일에 적힌 대로 7명 신청(남은 자리 3석)으로 보이게 됩니다.

  ② 남은 좌석 초과 신청을 막는 검증이 없습니다.
     - 현재 app/api/reserve/route.ts는 신청 인원이 '1명 이상'인지만 확인할 뿐, 남은 자리보다 많이 신청했는지(예: 1석 남았는데 2명 신청) 막아주는 코드가 없습니다.


2. 별도 유료 DB 없이 지금 쓰는 '구글 시트'만으로 해결할 수 있나요?

  네, 충분히 가능합니다! 지금 연결해 두신 구글 시트와 Apps Script를 그대로 데이터베이스처럼 활용하면 됩니다.

  다음 3가지만 추가하면 말씀하신 시나리오대로 완벽하게 작동합니다:

  ① 구글 Apps Script에 doGet 함수 추가 + 초과 예약 차단 (doPost 보완)
     - doGet 추가: 웹앱이 열릴 때 구글 시트의 "예약" 탭에서 강좌별 신청 인원 합계를 계산해 알려줍니다.
     - doPost 보완: A와 B가 거의 동시에 신청하더라도(LockService 활용), 시트의 현재 총 예약 인원을 먼저 합산해 보고 정원을 초과하면 "남은 좌석이 1석뿐입니다"라고 거절합니다.

  ② Next.js에 실시간 좌석 조회 API 추가 (/api/courses 등)
     - 페이지에 접속할 때마다 서버가 구글 시트(SHEET_URL)에서 강좌별 실제 예약 인원을 가져와 화면에 보여줍니다.

  ③ 프론트엔드 & 서버에서 잔여 좌석 제한 적용
     - 남은 자리가 1석이면 인원 입력칸의 최댓값(max)도 1명으로 제한하고, 마감(0석)이면 신청 버튼을 비활성화합니다.


3. 설계 시 선택할 수 있는 두 가지 운영 기준

  [기준 1: 구글 시트 순수 연동]
  - data/courses.js의 booked 숫자는 무시하고, 오직 구글 시트 "예약" 탭에 적힌 실제 신청자 인원 합계만 예약 인원으로 계산하는 방식.
  - 장점: 실제 운영할 때 가장 깔끔하며, 구글 시트에서 취소자 행을 지우면 웹앱의 남은 좌석도 자동으로 다시 늘어납니다.

  [기준 2: 기본값 + 시트 합산]
  - courses.js에 적어둔 기존 숫자(예: 엑셀 7명)에 구글 시트에 새로 쌓인 인원을 더해서(7 + 2 = 9명) 계산하는 방식.
  - 장점: 실습/시연용으로 미리 일정 인원이 찬 것처럼 보여주고 시작할 때 유용합니다.


--------------------------------------------------------------------------------
Part 2. 초기 예약자를 0명으로 세팅했을 때의 동작 원리
--------------------------------------------------------------------------------

[질문 2]
우선 수정하기 전에 지금 이 상태를 깃허브에 올리고 그 버전을 배포한 상태야.
그리고 수정을 하는데, 여기서는 기존의 예약자가 아무도 없는 거지.
그러면 기존의 예약자가 아무도 없는 상태로 코드의 기본을 바꾸고 나면 기준 1, 기준 2는 똑같은 게 되는 거지?

[답변 2]
네, 정확합니다! 완벽하게 이해하셨습니다.

data/courses.js의 모든 강좌에서 초기 예약 인원(booked)을 모두 0으로 바꿔두면:
  - 기준 1 (구글 시트 인원만 반영): 시트 신청 인원
  - 기준 2 (기본값 + 시트 인원 합산): 0 + 시트 신청 인원

결국 두 방식이 완전히 똑같이 동작하게 됩니다!

초기값을 0으로 두면 두 가지 장점이 더 생깁니다:
  1) 구글 시트를 아직 불러오는 중(로딩 순간)에도 화면이 '예약 0명'에서 자연스럽게 시작합니다.
  2) 나중에 오프라인 신청자 등이 생겨서 특정 강좌만 미리 2석을 빼두어야 할 때도 booked: 2로 숫자만 고치면 바로 반영되는 유연함까지 갖추게 됩니다.

Part 3. 버전 분리(v1 유지 + v2.1 신규 구축 및 배포)와 구글 시트 양방향 호환 전략
--------------------------------------------------------------------------------

[질문 3]
그러면 나는 변경된 내용을 skilltomoney-appv2.1 로 해서 깃허브에 올리고, 배포도 skilltomoney-appv2.1 로 해서 기존의 것과 지금 수정한 것을 구별해서 언제든 수정 이전 버전도 사용할 수 있도록 하고 싶은데 가능해?

[답변 3]
네, 완전히 가능합니다! 강의 시연이나 실제 운영을 병행하실 때 아주 좋은 방법입니다.

기존 버전(skilltomoney-app)은 그대로 살려두고, 새 버전(skilltomoney-appv2.1)을 완전히 독립된 별도 사이트로 만들고 배포하는 가장 깔끔한 구조는 다음과 같습니다:

1. 내 컴퓨터 폴더 분리
   - 기존 폴더: d:\skilltomoney\skilltomoney-app (건드리지 않고 수정 이전 상태로 그대로 보존!)
   - 새 폴더: d:\skilltomoney\skilltomoney-appv2.1 (여기에 복사본을 만들어 실시간 좌석 연동 기능으로 업그레이드)

2. GitHub 저장소(Repository) 분리
   - 기존 저장소: 그대로 유지
   - 새 저장소: GitHub에 skilltomoney-appv2.1 이름으로 새 저장소를 만들어 업로드

3. 배포 사이트(Vercel) 분리
   - 기존 배포 주소: 예전 버전 사이트가 그대로 계속 살아있음 (강의할 때 "수정 전 버전" 보여주기용으로 언제든 접속 가능!)
   - 새 배포 주소: Vercel에서 skilltomoney-appv2.1을 새로 연결해 배포 (skilltomoney-appv2-1.vercel.app 같은 새 주소 생성!)

4. 보너스 팁 (구글 시트 호환성)
   - 새로 작성하는 구글 Apps Script 코드(doGet 추가 + doPost 유지)는 이전 버전 앱과 새 버전(v2.1) 앱 양쪽 모두와 호환되도록 만들 수 있습니다.
   - 즉, 같은 구글 시트를 쓰셔도 되고, 아예 시트까지 깨끗하게 분리하고 싶으시면 새 구글 시트를 하나 더 만드셔도 됩니다.

지금 바로 진행할 순서대로 해주고, 구글 시트는 호환되도록 해주고, 지금의 대화도 기존 대화에 추가해서 txt 파일에 저장해줘.

[답변 4]
요청하신 모든 작업을 순서대로 깔끔하게 완료했습니다!

1. 완료된 작업 요약

  ① 독립 폴더 생성 및 Git 세팅 완료 (skilltomoney-appv2.1)
     - 기존 d:\skilltomoney\skilltomoney-app 폴더는 이전 버전 상태 그대로 보존했습니다.
     - 옆에 d:\skilltomoney\skilltomoney-appv2.1 폴더를 새로 만들고 Git 초기화(git init) 및 첫 커밋까지 완료해 두어 바로 GitHub에 올릴 수 있습니다.

  ② 초기 예약자 0명 세팅 및 실시간 좌석 연동 구현 (v2.1)
     - data/courses.js: 모든 강좌의 초기 booked 값을 0으로 변경했습니다.
     - app/api/courses/route.ts: 접속 시 구글 시트에서 강좌별 예약 인원 합계를 실시간으로 불러옵니다.
     - app/api/reserve/route.ts & app/page.tsx: 남은 좌석만큼만 인원 선택이 가능하도록 제한하고, 정원 마감 시 버튼을 비활성화 및 초과 신청을 차단합니다.

  ③ 구글 시트 양방향 호환 스크립트 완성
     - google-apps-script/Code.gs (기존 폴더와 v2.1 폴더 모두 동일하게 업데이트됨): 기존 버전(v1)과 새 버전(v2.1) 모두 하나의 구글 시트에서 충돌 없이 작동합니다.

  ④ 강의자료 .txt 파일 업데이트 완료
     - 강의자료_실시간_수강신청_좌석연동_QnA.txt (v1, v2.1 양쪽 폴더 모두 저장됨)


2. 마무리 적용 방법 (딱 2가지만 하시면 됩니다!)

  [단계 ①] 구글 시트 Apps Script 업데이트 (필수)
    1) 구글 시트 상단 메뉴에서 [확장 프로그램] -> [Apps Script]로 들어갑니다.
    2) 기존 코드를 지우고 google-apps-script/Code.gs 파일 내용을 전체 복사해 붙여넣고 저장(Ctrl + S)합니다.
    3) 우측 상단 [배포] -> [배포 관리] -> 연필 아이콘(수정) -> 버전: '새 버전' 선택 -> [배포]를 누릅니다.
       (웹 앱 URL이 그대로 유지되어 기존 버전 앱도 수정 없이 그대로 잘 돌아갑니다!)

  [단계 ②] GitHub에 skilltomoney-appv2.1 올리고 Vercel 배포하기
    1) GitHub에서 새 저장소 이름을 'skilltomoney-appv2.1'로 생성합니다 (README 체크 해제).
    2) 터미널에서 아래 명령어로 바로 푸시합니다:
       cd d:\skilltomoney\skilltomoney-appv2.1
       git remote add origin https://github.com/본인아이디/skilltomoney-appv2.1.git
       git push -u origin main
    3) Vercel에서 [Add New] -> [Project]를 눌러 방금 올린 skilltomoney-appv2.1을 선택하고,
       Environment Variables에 SHEET_URL 값만 넣어서 [Deploy]를 누르면 두 버전 모두 독립된 주소로 언제든 사용하실 수 있습니다!
